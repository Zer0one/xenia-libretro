First rolling release of the Zer0one Xenia Edge Libretro fork. Development follows `main`; release tags use `v0.1.0.N`, incrementing the fourth component.

### Changes

- Full integration of Xenia Edge `eb31a60`, preserving the Libretro frontend, frontend-driven vblank and excluded standalone components.
- Vulkan handoff resources retained per frontend sync slot. The macOS shared-queue path retains its CPU completion guard.
- Per-instance MoltenVK submission policy: asynchronous host submission with the recognized local driver correction, or synchronous compatibility mode with an on-screen notice on original drivers.
- Complete frontend audio blocks, silence padding for temporary source shortages, and fractional sample carry reset on content load/reset.
- Orderly guest shutdown and pause-watchdog join when native Quit / Cmd+Q bypasses Libretro unload.
- Build CI follows this fork's `main` branch.

### Download And Install

Platform ZIP packages contain the core, matching `.info`, build manifest and checksums. The shared remote workflow targets Windows x86_64, Linux x86_64/ARM64, macOS ARM64 and Android ARM64/x86_64. The exact successfully published targets are listed below; Android is non-blocking until further user instruction, and an exclusion after an Android failure is stated explicitly. Windows crash symbols are a separate ZIP tied to the same DLL hash. Install the core and information file in RetroArch's configured core and info directories. Use Vulkan, or Direct3D 12 on Windows. macOS minimum deployment target: 15.0.

MoltenVK and RetroArch are not included or replaced by this package. The core supports the original-driver compatibility path; the separately tested local MoltenVK corrections are documented in the repository. No firmware or BIOS is required for Xbox 360 content. Games and other copyrighted content are not included.

### Validation And Limits

The release is built, packaged and published by the GitHub Actions **Publish rolling core release** workflow, from tagged commit `f79f534d205413f26ee35c2381bc7c1e1584db7b` with platform Release settings. Desktop runners check native core loading and Libretro ABI/version; macOS also checks its ad hoc signature. Android receives static ELF architecture/export/dependency and 16 KiB alignment checks, not a device-runtime claim. A separate Ubuntu publication job verifies package checksums, the tagged source commit and CI-run provenance before uploading. The package manifest links the exact workflow run. Local installation uses the downloaded CI artifact with its matching `.info`.

Earlier same-source candidate tests established Daytona USA title/attract rendering, completed audio callbacks, two actual resets, content close, native Quit and installed Cmd+Q. Their exact binary identities and driver versions remain recorded in `CORE_LIFECYCLE.md`, `AUDIO_DIAGNOSTICS.md` and `VULKAN_PRESENTATION.md`. Those results are not relabeled as runtime tests of this freshly rebuilt release binary. No new game runtime or performance benchmark is part of release packaging.

Remaining work includes audio continuity under slow presentation, performance profiling, controlled gameplay/physical controllers, other-platform runtime validation and System Link. Driver reproducers establish their documented correctness results, not an automatic FPS improvement. Build and ABI checks do not establish gameplay on any platform. Android device runtime and cross-platform frontend behavior remain separate validation work.
